# ESP32 最小硬件验证套件 - 测试说明

本正如您所要求的，本文档旨在说明如何使用该测试套件来验证 Wokwi 仿真环境下的 ESP32 硬件连接。

## 1. 目录结构

项目采用了模块化设计，主要文件结构如下：

```
/
├── drivers/            # 硬件驱动库
│   ├── display.py      # OLED 显示驱动 (SSD1306)
│   ├── sensors.py      # 传感器驱动 (DHT22, LDR)
│   ├── actuators.py    # 执行器驱动 (LEDs, Buzzer)
│   ├── ir.py           # 红外接收驱动
│   └── ssd1306.py      # 基础 OLED 驱动库
├── doc/
│   └── 测试说明.md      # 本文档
└── test_suite.py       # 主测试入口脚本
```

## 2. 硬件连接定义

请确保 Wokwi 中的连线与以下定义一致：

| 模块 | 组件 | 引脚/备注 |
| :--- | :--- | :--- |
| **I2C OLED** | SSD1306 | SCL=GPIO22, SDA=GPIO21 |
| **传感器** | DHT22 温湿度 | GPIO15 |
| | LDR 光敏电阻 | GPIO34 (模拟量) |
| **执行器** | 加热器 (红灯) | GPIO25 |
| | 风扇 (绿灯) | GPIO26 |
| | 补光灯 (白灯) | GPIO14 |
| | 加湿器 (蜂鸣器) | GPIO27 (测试频率 2000Hz) |
| **输入** | IR 红外接收 | GPIO35 |

## 3. 如何运行测试

1. 打开 Wokwi 仿真器。
2. 确保所有文件（drivers 文件夹及其内容, test_suite.py）都已上传或存在于文件系统中。
3. 运行 `test_suite.py`。

在 MicroPython 控制台中执行：

```python
import test_suite
suite = test_suite.HardwareTestSuite()
suite.run_all_tests()
```

或者直接运行脚本（如果 IDE 支持）。

## 4. 测试流程与预期结果

测试套件将按顺序执行以下 4 个步骤，每个步骤间隔 2 秒：

### [TEST 1] OLED 显示测试 (OLED Display)
*   **动作**：初始化屏幕，清屏，绘制边框，显示文字。
*   **预期**：屏幕上出现一个矩形框，内部显示 "Modular Test" 字样。如有报错，控制台会输出 I2C init failed。

### [TEST 2] 传感器测试 (Sensors)
*   **动作**：读取一次 DHT22 和 LDR 数据。
*   **预期**：控制台打印当前温度、湿度和光照强度（ADC数值 0-4095）。
    *   示例：`DHT22: 25.0C, 60.0%`
    *   示例：`LDR: 2048`

### [TEST 3] 执行器测试 (Actuators)
*   **动作**：
    1.  控制红、绿、白三个 LED 进行一次呼吸灯效果（渐亮 -> 渐暗）。
    2.  控制蜂鸣器以 2000Hz 频率鸣叫 0.5 秒。
*   **预期**：视觉上看到 LED 亮度平滑变化；听到蜂鸣器“滴”一声。

### [TEST 4] 红外信号测试 (IR Signal)
*   **动作**：读取 GPIO35 电平状态。
*   **预期**：控制台打印当前引脚电平（0 或 1）。
    *   示例：`IR Pin State: 1` (默认高电平，按下遥控器可能变低)

## 5. 故障排除

*   **ImportError**: 检查 `drivers` 文件夹是否完整，在该文件夹下是否有 `__init__.py` (MicroPython 通常不需要，但确保路径正确)。确保 `ssd1306.py` 在 `drivers/` 目录下。
*   **OSError: [Errno 19] ENODEV**: 通常是 I2C 设备未找到。检查 GPIO21/22 连线以及 OLED 是否供电。
*   **DHT22 读数失败**: 检查 GPIO15 连接及上拉电阻（Wokwi 中通常只需直连）。
